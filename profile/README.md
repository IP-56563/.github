<h2>一、速度不是单一指标，是四个数</h2>

<p>宣传里的"快"通常是混淆概念。完整的网速由四部分构成：延迟（数据往返时间）、抖动（延迟的波动）、丢包率（丢失的数据比例）、带宽（吞吐能力）。不同业务对四者的敏感度完全不同：后台操作类业务对延迟和丢包敏感，传文件看带宽，直播推流最怕抖动。拿单一"下载速度"宣传的快，对不上你的业务就等于没测。</p>

<h2>二、延迟的合理区间</h2>

<p>物理距离决定延迟下限，跨太平洋不可能低于光速。参考区间：美国西海岸到中国大陆约 150–200ms，东海岸约 200–250ms，同州内通常 30ms 以内。宣传"美西节点"却测出 250ms 以上的，大概率绕了路；反过来延迟低得反常（比如跨洲 40ms），要确认是不是本地加速节点冒充。延迟本身不致命，但抖动大到 100ms 以上，页面会明显一顿一顿。</p>

<h2>三、稳定性怎么看：先问口径，再自己测</h2>

<p>"99.9% 可用率"要拆开问：按月统计还是按天？允许的月度中断时长是多少？上游运营商路由调整算不算故障？真中断了怎么赔——退款、补时长还是换IP？口径问清楚，比自己测一个月更能说明服务商的态度。自己测的方法：连续 24–72 小时定时 ping 加周期性访问目标站点，记录掉线次数、每次恢复时长、延迟抖动曲线。一周的数据足以劝退大多数问题线路。</p>

<h2>四、商家的三个障眼法</h2>

<p>1. ICMP 漂亮、TCP 难看：ping 通得飞快，实际网页打不开——不少线路对 ping 宽松、对 TCP 连接限速，必须测应用层。2. 峰值带宽冒充持续带宽：测速瞬间跑满，持续传输十分钟就掉速，要分瞬时和持续两次测。3. 单点测试冒充整段：测试IP是段里最好的一个，买到的不是同一个——坚持要求"测试IP即交付IP"，或同段随机抽测。</p>

<h2>五、到手验收流程</h2>

<p>按顺序五步：1. whois/ASN 核查归属；2. 代理库与黑名单查询；3. 24 小时 ping 记录掉线与抖动；4. 目标平台实际登录，观察验证频率和加载速度；5. 核对带宽和并发是否符合订单。全过再扩容付款，任何一步存疑就换段。</p>

<h2>六、常见问题</h2>

<h3>ping 通但页面打不开，是什么问题？</h3>

<p>典型的 TCP 层限速或路由劫持，ICMP 被放行了。换应用层工具测（curl 计时、浏览器实际加载），以应用层结果为准。</p>

<h3>延迟忽高忽低正常吗？</h3>

<p>公网线路有波动正常，但稳定段落的抖动应该在 20–30ms 内。频繁跳到两倍以上，说明路由在不停调整，长期用会很难受。</p>

<h3>需要 7×24 小时盯着测吗？</h3>

<p>采购期测 24–72 小时足够，之后靠商家的监控和更换政策兜底。真需要持续监控的业务，直接上带 SLA 的双ISP或专线更靠谱。</p>
